## 1. Что такое V1 по ТЗ и что из этого уже было

V1 готова, когда человек в настоящем интерфейсе отправляет промпт, получает настоящую
генерацию через Higgsfield, обновляет страницу без потери статуса, смотрит и скачивает MP4
и оставляет оценку.

| Цель ТЗ | До аудита | После Phase 1–4 |
|---|---|---|
| Проект, промпт, фото | есть | без изменений |
| Только поддерживаемые настройки | монтажные настройки есть; «настоящее видео / превью» решает сборщик | без изменений |
| Настоящая генерация Higgsfield | есть, но номер задачи жил в памяти | номер в базе, повтор забирает результат |
| Статус переживает обновление страницы | да (база + опрос 3 с) | без изменений |
| Статус переживает перезапуск сборщика | клип заказывался заново | забирается та же задача |
| Просмотр и скачивание MP4 | есть | без изменений |
| История | «Мои видео» | + фильтр по состоянию |
| Оценка результата | нет | «Хороший результат» / «Нужно улучшить» + причины + комментарий |
| Видно, кто сделал клип | нет (только в базе) | на странице проекта |

## 2. Фактический путь генерации

1. Форма [Generator.tsx](../web/app/components/Generator.tsx) → фото через
   [uploads/route.ts](../web/app/api/uploads/route.ts) → проект через
   [projects/route.ts](../web/app/api/projects/route.ts): проверки, лимиты (1 одновременно и 5 в
   день на человека, 60 в день на сервис), строки `projects` и `jobs`.
2. Сборщик [main.py](../worker/main.py) забирает задачу `claim_next_job` (`FOR UPDATE SKIP LOCKED`)
   и зовёт [pipeline.run_project](../worker/pipeline.py).
3. Сценарий → голос → раскадровка → картинки; каждый готовый шаг пишется в базу и при повторе
   пропускается.
4. Настоящее видео — только при `MVP_SAFE_MODE=0` и `VIDEO_MODE=provider`, только для кадров,
   отмеченных планировщиком (цель SMART — 70% длины). Модель выбирает
   [providers.py](../worker/providers.py).
5. Higgsfield ([video_step.py](../worker/steps/video_step.py)): `POST /{модель}` → `request_id` →
   опрос `GET /requests/{id}/status` раз в 5 с до 15 минут → скачивание `video.url`. Контракт —
   их `openapi.json` 2.0.0. Вебхуков, ключа идемпотентности и цены в API нет.
6. Клип → публичное хранилище Supabase `media` (постоянная ссылка, временная ссылка Higgsfield не
   используется) → кадр получает `real_video`, провайдера и модель.
7. FFmpeg-монтаж → [quality.py](../worker/quality.py) → до двух кругов починки → `final.mp4` →
   `done` или `done_degraded` с долей настоящего видео и причиной.
8. Страница [status.tsx](../web/app/[lang]/projects/[id]/status.tsx) опрашивает
   [projects/[id]/route.ts](../web/app/api/projects/[id]/route.ts) раз в 3 с.

## 4. Деньги в этой работе

- Платных вызовов агентом: **0**. Классификатор разрешений закрыл и чтение боевой базы, и
  платный вызов — по CLAUDE.md §1 деньги тратит человек.
- Бесплатная проверка на настоящем API: неверный ключ → `HTTP 401 Invalid credentials`, задача не
  создана.
- Платная проверка готова к одному двойному клику: `worker/Проверить Higgsfield.command` — один
  клип 5 с (≈$0.09 по счёту, $0.35 по учёту), процесс намеренно умирает после постановки, второй
  запуск забирает ту же задачу.

## 5. Что нужно от основателя

1. **Вставить миграцию** [0006](../supabase/migrations/0006_provider_requests_and_feedback.sql) в
   Supabase → SQL Editor → Run. До неё сборщик и сайт работают как раньше, просто без номера
   задачи и без оценки.
2. **Закрыть два старых сборщика и запустить один новый** двойным кликом «Запустить
   сборщик.command» — иначе пользователей обслуживает код сентября.
3. **Двойной клик «Проверить Higgsfield.command»** — платная проверка V1 (≈$0.09).
4. **Цена клипа из кабинета Higgsfield** — чтобы потолок бюджета считал по правде.
