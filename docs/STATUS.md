> **Это единственное место, где живут статусы.** Не в чате, не в голове, не в Bible.
> Строка без команды проверки и её реального вывода — это не статус, а мнение.

## Метки

| Метка | Что означает | Чем подтверждается |
|---|---|---|
| `VERIFIED` | проверено **в текущей сессии, в указанной среде** | команда + её вывод в этой таблице |
| `IMPLEMENTED_UNTESTED` | код существует, поведение не проверено | — |
| `PLACEHOLDER` | модуль/интерфейс есть, реальной интеграции нет | — |
| `PLANNED` | только в планах | — |
| `BLOCKED` | известный внешний блокер | описание блокера |
| `REGRESSED` | было `VERIFIED`, сломалось | что именно сломалось |
| `DOC_DRIFT` | документ и код расходятся | в чём расхождение |

### Правила

1. `VERIFIED` ставится **только** при наличии вывода команды, полученного в текущей сессии.
   «Прочитал код, выглядит правильно» — это `IMPLEMENTED_UNTESTED`, без исключений.
2. Статус привязан к **среде**, а не только к фиче. `VERIFIED` на Windows ничего не говорит о
   Linux — см. проблему шрифтов для субтитров в [BIBLE.md §3](BIBLE.md#3-где-мы-на-самом-деле-гейты-вместо-процентов).
3. Любое изменение файла на активном пути **автоматически понижает** все зависящие статусы до
   `IMPLEMENTED_UNTESTED`.
4. Метка `VERIFIED_PREVIOUS` из версии 1.0 **упразднена**. «Работало в прошлой сборке» — это не
   статус, а воспоминание.
