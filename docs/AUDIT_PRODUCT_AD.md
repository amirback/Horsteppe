## 1. CURRENT ACTIVE FLOW

`main.py` → `claim_next_job()` → `pipeline.run_project()` — единственный
оркестратор. Шесть этапов, каждый возобновляемый (готовый ассет при повторе
пропускается, провайдеру не платят дважды):

| # | Этап | Модуль | Что делает |
|---|---|---|---|
| 1 | Сценарий | `steps/script_step.py` | LLM (OpenRouter/Anthropic) → `{title, continuity, scenes:[{narration, image_prompt, shots[]}]}` |
| 2 | Озвучка | `steps/tts_step.py` | ElevenLabs → mp3 на сцену. **Точная длина озвучки — источник истины по таймлайну** (CLAUDE.md §8) |
| 3 | Раскадровка | `steps/shot_plan.py` | сцена → 6–10 кадров, сумма = озвучке до миллисекунды; крупность, движение камеры, важность, цель покрытия |
| 4 | Кадры | `steps/image_step.py` | цепочка провайдеров pollinations → together → fal, 1 картинка на **кадр** |
| 5 | Видео | `steps/video_step.py` | fal Kling **image-to-video** из картинки кадра — только если платное разрешено |
| 6 | Монтаж | `steps/render_step.py` + `media.py` | сегмент на кадр → склейка → xfade между сценами → звук → субтитры → музыка → `validate_final` → загрузка |

Вход: `projects` (topic, style, duration_sec, aspect_ratio). Выход: `renders.final_video_url`.

**Тесты на этой ревизии:** `pytest tests/ -q` → **122 passed за 168 с** (mac, эта сессия).

## 2. REAL VIDEO PATH — существует и доходит до таймлайна

Это главная новость аудита: **требование ТЗ §18 уже выполнено.**

```
shot.image_url (публичный URL Supabase)
  → video_step.generate_clip(cfg, image_public_url, video_prompt, out)
  → fal-ai/kling-video/v2.1/standard/image-to-video, duration="5"
  → shots.video_url + generation_mode='real_video'
  → pipeline: if shot.get("video_url"): entry["clip_path"] = ...
  → render_step.make_clip_segment → финальный MP4
```

Ключевая строка — [pipeline.py](../worker/pipeline.py) в блоке монтажа:
готовое настоящее видео используется **безусловно**, без оглядки на текущий
режим. Прежнее условие требовало ещё и `VIDEO_MODE=provider`, из-за чего
оплаченный клип молча заменялся зумом по картинке — ровно тот дефект, который
ТЗ описывает как «real provider files are generated but ignored». Исправлено
коммитом `fda41e5` «Бесплатное доказательство: настоящий клип доходит до
финального ролика».

**Что уже правильно:**

- решение «настоящее видео или движение по картинке» принимается **по кадру**,
  а не одним тумблером на ролик (`shot_plan.preferred_mode`);
- падение провайдера на одном кадре не роняет проект — кадр в одиночку
  откатывается на движение по картинке, причина пишется в `failure_reason`;
- `real_video_coverage()` считается по таймлайну и **не засчитывает зум по
  фотографии** — на этом различении стоит обещание продукта;
- цель покрытия — лестница приоритетов: крючок и кульминация получают дорогую
  генерацию первыми (`assign_generation_modes`, `COVERAGE_TARGETS`:
  preview 0 / draft 0.35 / smart 0.70 / cinematic 0.90 — цифры ТЗ §4).

**Чего не хватает:** покрытие считается, но **никуда не сохраняется и
пользователю не показывается**; статуса `COMPLETED_DEGRADED` (ТЗ §32) нет —
ролик с нулевым покрытием отдаётся как обычный успех.

## 5. CURRENT QUALITY BOTTLENECKS — проверено чтением кода

Отсортировано по вкладу в ощущение «дёшево», а не по порядку ТЗ.

| # | Причина | Где | Доказательство |
|---|---|---|---|
| 1 | **Исходник кадра 576×1024, растягивается до 1080×1920** | `image_step._via_pollinations` | Pollinations всегда отдаёт 576×1024, что бы ни просили — `VERIFIED` 2026-09-11 в STATUS. Дальше апскейл в 1.9 раза: мягкая картинка на весь ролик |
| 2 | **До четырёх поколений H.264 на одном пикселе** | `media.py` | сегмент кадра (CRF 20) → `concat_segments` **перекодирует** сцену → `concat_with_transitions` (xfade) → `burn_subtitles`. Только `mux` и `mix_music` идут через `-c:v copy` |
| 3 | **Нет `-movflags +faststart`** | `media._ENCODE` | ТЗ §26 требует прямо; без него браузер начинает играть только после полной загрузки |
| 4 | Промпт без референса | `pipeline.py` | описание мира — строка `continuity`, приклеенная в начало промпта каждой сцены. Товар в генерацию физически не попадает |
| 5 | Выбор провайдера — порядок в переменной окружения | `config.image_provider`, `image_step.generate_image` | цепочка по очереди, без возможностей, без причины выбора, без учёта типа кадра. Модель видео одна, зашита в `FAL_VIDEO_MODEL` |
| 6 | Потолка бюджета нет | `safe_mode.py` | `is_paid_allowed()` — да/нет. Оценки до вызова и отказа по остатку (ТЗ §17) не существует |
| 7 | Проверка качества поверхностная | `media.validate_final` | есть: длительность, потоки, разрешение, яркость, пик звука, застывший финал. **Нет:** покрытие движением на финальном файле, список замерших участков, покадровая статика, битые ассеты |
| 8 | Автопочинки нет | `pipeline.py` | сбой клипа = тихий откат кадра на зум. Кадр не перегенерируется никогда, `retry_count` не растёт |

**Не подтвердилось** (ТЗ перечисляет как возможные причины): слабая
раскадровка, однообразное движение камеры, одна картинка на сцену, лишние
пересжатия **звука**, отсутствие таймаутов, утечка секретов. Это уже закрыто.

## 8. Что упирается не в код — решения основателя (CLAUDE.md §9)

1. **Платный провайдер видео заблокирован.** STATUS 2026-09-09: fal.ai
   «User is locked. Reason: Exhausted balance». Приёмочные тесты ТЗ §33 и §34
   **обязаны** сделать настоящий image-to-video: без живого аккаунта они
   недостижимы, и никакой код этого не обойдёт.
2. **Цена вопроса.** Kling 5-секундный клип — $0.35. Ролик 30 с при покрытии
   70% ≈ **$1.5** против нынешних $0.068. Двадцатикратный рост себестоимости
   при отсутствии приёма платежей (Stripe в Казахстане недоступен).
3. **Применение миграции** к боевой базе — сетевое действие с сервисным
   ключом. Агент готовит SQL, применяет человек.
4. **Честная пометка в интерфейсе.** ТЗ §14 и §30 запрещают выдавать зум по
   фотографии за настоящее видео. Сейчас пометки нет ни в одном режиме.
