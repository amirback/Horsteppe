## 1. Продукт в одном экране

**Horsteppe** — AI-режиссёр и AI-монтажёр. Пользователь описывает ролик обычными словами и
получает готовый смонтированный MP4 с озвучкой и субтитрами.

Внутреннее имя оркестратора движка — **ReelForge**. Публичный бренд везде — **Horsteppe**.

Конвейер:

```
идея → сценарий → сцены и кадры → визуал → голос → субтитры → монтаж → MP4
```

**Ключевая инженерная идея — Smart Visual Budget.** Не каждая секунда ролика стоит одинаково.
Дорогая AI-видеогенерация покупается только для сцен, где движение реально работает на кадр;
остальное собирается локально движением камеры по сгенерированному изображению. Это
единственная содержательно нестандартная идея проекта — но это **стратегия себестоимости, а не
защита от конкурентов**. Подробнее в [MONEY.md](MONEY.md).

### Чего в этом документе больше нет

Формулировка «наш moat — AI Director + AI Editor + Smart Router» удалена из позиционирования.
На сентябрь 2026 это описание категории, а не отличие: то же самое поставляют InVideo Agent One,
HeyGen Video Agent и агрегаторы моделей уровня fal.ai за $7–29 в месяц. Слово *moat* не
употребляется, пока нет трёх цифр из раздела [7](#7-позиционирование-и-рынок).

## 2. Развилка кодовых баз — решение №1

**Это самое дорогое нерешённое решение в проекте. Всё остальное ждёт.**

На диске существуют две разные кодовые базы одного продукта:

| | `AI_Video_Studio_v3` (движок) | `~/Desktop/ai video` (web + worker) |
|---|---|---|
| Что это | Python-конвейер: Director, SceneBuilder, VisualBudgetPlanner, стадии рендера | Next.js + Supabase + Python-воркер |
| Дата | правится до сих пор | последний коммит 06.08.2026 |
| Сильная сторона | **качество ролика**: драматургия, планирование сцен, умный бюджет визуала | **доставка**: очередь, resume, лимиты, авторизация, деплой |
| Очередь задач | нет | Postgres, `FOR UPDATE SKIP LOCKED`, перезапуск зависших |
| Возобновление после сбоя | нет | есть, по сценам — готовые сцены не перегенерируются |
| Учёт затрат | нет | таблица `cost_events` |
| Лимиты на пользователя | нет | одновременных 1, в сутки 5 |
| Безопасный режим без платного видео | **нужно сделать** | есть: `VIDEO_MODE=kenburns` |
| FFmpeg на сервере | ставить руками | статический, через `imageio-ffmpeg` |
| Изоляция проектов | общая папка `output/` | по `project_id` |
| Хостинг | нет | привязан к Vercel |

**Что это значит.** План «написать FastAPI-обёртку над v3 с нуля» означает второй раз построить
слой, который уже написан месяц назад и местами сильнее, чем то, что документ версии 1.0 считал
недостижимым. Для команды из двух человек это 2–3 недели перед акселератором, потраченные
впустую.

### Рекомендация

> **v3 — донор качества. `ai video` — база продукта.**
> Переносим стадии и промпты v3 внутрь существующего `worker/steps/`, а не наоборот.
> FastAPI-обёртка не пишется вообще: HTTP-слой уже есть.

Из v3 переносится то, чего в `ai video` нет: Director и планирование сцен, Smart Visual Budget,
тексты промптов, субтитры (SRT + вшивание), переходы, выбор формата кадра.
Из v3 **не** переносится архитектура — `engine/` vs `engine_v2/`, brain, task_graph, campaigns.

### Что нужно от основателя, чтобы закрыть развилку

Ответ на четыре вопроса — примерно полдня работы:

1. **Получался ли из `~/Desktop/ai video` реальный MP4 через браузер?** Если да — база выбрана.
   Если нет — записать конкретные причины («падает на шаге X»), а не «оно старое».
2. **Жив ли аккаунт fal.ai?** `ai video` целиком стоит на нём (кадры Flux, видео Kling), а
   документ 1.0 прямо запрещал его пополнять. Одно из двух утверждений должно быть отменено.
3. **Что физически лежит в текущей рабочей копии v3 на Windows** — см. [Gate 0](#gate-0).
4. **Какой LLM-стек оставляем:** OpenRouter (реселлер, у части провайдеров за ним включено
   обучение на промптах) или прямой Anthropic. Для продукта, куда клиенты пишут бренд-информацию,
   это ещё и юридический вопрос, не только ценовой.

**Решение записывается сюда, одной строкой, с датой.** До этого момента любой план Wave 1
ведёт к двойной работе.

```
РЕШЕНИЕ ПО КОДОВОЙ БАЗЕ: базой продукта становится `ai video`.   дата: 2026-09-06
v3 — донор идей (Director, планирование сцен, Smart Visual Budget, промпты, субтитры).
```

### Обоснование — проверено, а не предположено (06.09.2026)

**Движок v3 не собирает видео.** Архив `AI_Video_Studio_v3.zip` распакован и измерен:
162 Python-файла, **46 КБ кода суммарно**, 32 файла пустые, самый большой — 2.6 КБ.
Поиск по всему дереву: `subprocess` — **0 файлов**, `zoompan` — 0, `libx264` — 0, `runway` — 0.
Это значит, что FFmpeg не запускается никогда и **видеофайл не создаётся ни разу**.

Три ключевых файла целиком:

```python
# engine_v2/editor/ffmpeg_exporter.py — 169 байт
class FFmpegExporter:
    def export(self, context):
        print("[FFMPEG EXPORT]")
        context.final_video = "output/final.mp4"   # строка, а не файл
        return context

# engine_v2/render_pipeline/export_stage.py — 156 байт
class ExportStage:
    def run(self, context):
        print("[EXPORT]")
        context.final_video = "output/movie.mp4"   # другая строка, тоже не файл
        return context

# engine_v2/editor/movie_renderer.py — 116 байт
class MovieRenderer:
    def build(self, context):
        print("[MOVIE RENDERER]")
        return context
```

Весь блок `VERIFIED_PREVIOUS` версии 1.0 — движение по кадру, вшивание субтитров, переходы,
аудиомикс, финальный `movie.mp4` — этим кодом не подкреплён.

> **Оговорка.** Проверен архив от 06.08.2026, а не рабочая копия `WAVE1_SPEEDRUN_FIXED` на
> Windows — её на этом компьютере нет. Но патчи, описанные в версии 1.0 (кодировка вывода,
> таймауты опроса), не создают конвейер рендера из ничего. Если на Windows иначе — покажите
> `movie.mp4` с датой, и решение будет пересмотрено.

**`ai video` собирает видео по-настоящему.** 29 файлов, 2457 строк, и в них:

| Что | Как сделано |
|---|---|
| FFmpeg | статический бинарник через `imageio-ffmpeg` — на сервере ставить нечего |
| Движение по кадру | Ken Burns с апскейлом ×2 перед `zoompan` — против дрожания |
| Короткий премиум-клип | `tpad=stop_mode=clone` — заморозка кадра, а не заметная петля |
| Порядок стадий | **озвучка раньше визуала** — длина сцены равна реальной длине голоса |
| Возобновление | `if scene.get("audio_url"): continue` — сбой на 4-й сцене не оплачивает заново 1–3 |
| Учёт затрат | `db.log_cost()` на каждом платном вызове, цены в одном словаре `COSTS` |
| Сценарий | Claude со схемой структурированного вывода, обработка отказа модерации, подсчёт по реальным токенам |
| Бесплатный режим | `SCRIPT_MODE=mock` и `VIDEO_MODE=kenburns` — весь конвейер прогоняется за $0 |
| Очередь | Postgres, `FOR UPDATE SKIP LOCKED`, перезапуск зависших задач |
| Таймауты | `subprocess` 600 с, HTTP 120 с — то, что в v3 значилось открытой задачей |

То есть шесть из восьми пунктов Wave 1 там уже закрыты, включая безопасный режим.

### Сопутствующие решения (06.09.2026)

| Вопрос | Решение | Почему |
|---|---|---|
| LLM-стек | **прямой Anthropic** | уже используется в базе; у API нет обучения на данных клиента по умолчанию — важно, раз клиенты пишут бренд-информацию |
| Запрет на fal.ai | **снят** | вся генерация кадров стоит на нём; при этом нужен запасной провайдер изображений |
| Формат кадра | **9:16**, зафиксирован | так уже сделано в базе, и это верный выбор для первых пользователей |
| Приём платежей | **merchant of record** (Paddle / Lemon Squeezy) | Stripe в Казахстане недоступен, а перевод на карту физлица не показать в акселераторе |
| Премиум-видео в Wave 1 | **выключено** | `VIDEO_MODE=kenburns` — единственный режим до первых тестеров |

### Чего в базе нет и что переносим из v3

Субтитры (SRT + вшивание) · Director и планирование сцен глубже, чем сейчас ·
Smart Visual Budget · переходы между сценами · выбор формата кадра · пресеты стиля.

## 3. Где мы на самом деле: гейты вместо процентов

Проценты готовности из версии 1.0 (90% / 85–90% / 65–75% / …) **удалены**. Они не были привязаны
ни к одному критерию и противоречили собственному признанию документа, что полный безопасный
прогон ни разу не пройден после последних правок. В акселераторе на процентах без артефактов
ловят первым же вопросом «покажи».

Вместо них — гейты. Гейт либо пройден с артефактом, либо не пройден. Третьего нет.

| Гейт | Что означает | Артефакт-доказательство | Статус |
|---|---|---|---|
| <a name="gate-0"></a>**Gate 0** | Инвентаризация: известно, какой код реально существует | архив v3 распакован и измерен; `ai video` прочитан и перенесён в репозиторий | ✅ **пройден 06.09.2026** |
| **Gate A** | Безопасный сквозной прогон: из промпта получается играбельный MP4 без единого платного видеовызова | путь к файлу, вывод `ffprobe`, лог без обращений к платным провайдерам, **прогон в том же Docker-образе, что поедет в прод** | ❌ не пройден |
| **Gate B** | Веб-продукт: незнакомый человек с телефона получает MP4 без вашей помощи | URL, запись экрана | ❌ не пройден |
| **Gate C** | 3 внешних тестера получили видео самостоятельно | 3 ссылки на результаты + их отзывы | ❌ не пройден |
| **Gate D** | Первый платёж | подтверждение оплаты | ❌ не пройден |
| **Gate S** | Сайт продукта опубликован | https://horsteppe.vercel.app — три языка, en/ru/kk | ✅ **пройден 05.09.2026** |
| **Gate A½** | Ядро рендера собирает настоящий MP4 | локальный прогон: 4 сцены, два формата, субтитры, расхождение с голосом 0.000 с | ✅ **пройден 06.09.2026** |

### Важная оговорка про статусы «работало раньше»

В версии 1.0 почти весь ценный функционал (локальное движение по кадру, Runway, ElevenLabs,
синхронизация, субтитры, вшивание, переходы, аудиомикс, финальный `movie.mp4`) стоял с меткой
`VERIFIED_PREVIOUS` — «работало в одной из прошлых сборок».

Это не статус, а технический долг с неизвестным сроком годности, по двум причинам:

1. **После него были системные патчи** — UTF-8 в выводе, замена цикла опроса, таймауты. Любой
   из них мог сломать что угодно ниже по цепочке.
2. **Всё это верифицировано на конкретной Windows-машине с конкретной сборкой FFmpeg.** При
   переезде на Linux/Docker — а он неизбежен — первым отваливается вшивание субтитров: оно
   зависит от шрифтов с кириллицей, которых в облегчённых контейнерах нет, и субтитры молча
   исчезают или превращаются в квадраты. Экранирование фильтров FFmpeg под Windows и Linux тоже
   разное.

**Правило теперь такое:** статус хранится только в [STATUS.md](STATUS.md), в формате
`элемент | среда | дата | команда проверки | её вывод`. Любое изменение файла на активном пути
автоматически понижает зависящие статусы. «Прочитал код, выглядит правильно» — это
`IMPLEMENTED_UNTESTED`, без исключений.

### Отдельное предупреждение, требующее проверки

Аудит августовского архива `AI_Video_Studio_v3.zip`, лежащего на Mac, показал картину, которая
не сходится с описанием движка: 161 Python-файл общим объёмом 46 КБ, 32 файла пустые, ни одного
вызова FFmpeg, а `ExportStage` и `FFmpegExporter` просто присваивают строку с именем файла и
печатают сообщение — причём **разные** строки, и ни один из них файл не создаёт.

**Это не приговор текущему коду.** Проаудирован августовский архив, а не ваша рабочая копия
`AI_Video_Studio_WAVE1_SPEEDRUN_FIXED` на Windows — её на этом компьютере нет. Но пока Gate 0 не
пройден, исходить нужно из худшего.

**Проверка занимает пять минут и не стоит ни копейки.** В PowerShell, в папке рабочей копии:

```powershell
Get-ChildItem -Recurse -Filter *.py | Select-String -Pattern 'subprocess|ffmpeg|imageio' | Measure-Object
Get-ChildItem -Recurse -Filter *.py | Select-String -Pattern 'zoompan|drawtext|libx264' | Measure-Object
```

Если оба счётчика нулевые — движка, который монтирует видео, в этой копии нет, и раздел
[2](#2-развилка-кодовых-баз--решение-1) решается автоматически в пользу `ai video`.
Плюс покажите любой реально существующий `movie.mp4` с датой создания.

## 4. Активный путь

Единственная цепочка, которую нельзя ломать. Всё, чего здесь нет, считается замороженным
legacy — его не чинят, не улучшают и не удаляют без отдельного разрешения.

```
app.py
 └─ core/reelforge.py                     оркестратор
     ├─ models/project.py                 состояние фильма
     ├─ engine/director.py                сценарий
     ├─ engine/scene_builder.py           сцены, тайминг, плотность текста
     ├─ engine/visual_budget_planner.py   где нужен премиум, где хватит движения по кадру
     ├─ engine/asset_reuse_engine.py      переиспользование локаций и объектов
     └─ engine_v2/render_pipeline/pipeline.py → StageManager
```

Стадии рендера — **порядок изменён относительно версии 1.0**:

```
ImageStage → VoiceStage → VideoStage → MusicStage → SubtitleStage → EditingStage → ExportStage
                ↑ перенесён выше
```

**Почему голос переехал вперёд видео.** Документ сам фиксирует: реальная длительность озвучки —
это master clock, и в одном из прогонов вышло 51.13 с против запрошенных 60. Но премиум-секунды
покупались под план на 60 с, а таймлайн пересобирался под 51 — то есть ~15% оплаченного видео
выбрасывалось. Озвучка стоит примерно $0.04 на ролик, видео — в пятьдесят раз дороже. Сначала
синтезируем голос, измеряем его реальную длину, пересчитываем сцены и только потом покупаем
премиум-секунды. Это перестановка стадий, без новых зависимостей.

Монтаж:

```
TimelineBuilder → TransitionEngine → SubtitleRenderer → AudioMixer → MovieRenderer → FFmpegExporter
```

## 5. Wave 1: первые 14 дней

**Цель:** один промпт → один играбельный MP4 → через веб-интерфейс, в руках у постороннего
человека.

Порядок в версии 1.0 был выстроен по техническому риску (таймауты → безопасный режим → прогон →
заморозка → FastAPI → фронт → деплой → тестеры) и давал первый контакт с живым человеком на
четвёртой неделе. Ниже порядок, который отвечает на главный вопрос проекта раньше.

> **Главная неопределённость — не «упадёт ли конвейер», а «примет ли живой человек получившийся
> ролик».** Конвейер, который не падает, но делает ролики, которые никто не выложит, стоит ноль.

### День 0 (полдня) — развилка

Ответить на четыре вопроса из раздела [2](#2-развилка-кодовых-баз--решение-1) и записать решение.
**Критерий:** решение о базе продукта зафиксировано одной строкой с датой.

### Дни 1–2 — безопасный режим и изоляция проектов

`MVP_SAFE_MODE` — **первое** изменение в коде, до всех таймаутов. Причина простая: пока нет
выключателя, каждая проверка таймаутов Runway идёт по платному пути — вы платите Runway за то,
чтобы научиться не зависать на Runway.

Разбивается на три маленькие задачи:
- **3a** — флаг в конфиге и одна функция-чекпойнт `is_paid_video_allowed()`;
- **3b** — все платные вызовы проведены через неё;
- **3c** — несостоявшееся решение планировщика пишется в метаданные («сцена 2 = AI_VIDEO,
  исполнено как IMAGE_MOTION»), чтобы позже посчитать, сколько премиум-секунд вы бы купили.

Значение по умолчанию — **безопасное**. Платный путь включается только явным `MVP_SAFE_MODE=0`.

**Критерий:** 5 прогонов подряд, ноль исходящих запросов к платным видеопровайдерам в логах,
5 играбельных MP4, `ffprobe` проходит.

### День 3 — десять роликов и честная оценка

Сгенерировать 10 роликов на 10 **реальных** темах (не тестовых). Оценить каждый бинарно:
«выложил бы это в свой профиль без правок — да/нет». Записать три главные причины «нет».

**Критерий:** есть число M из 10 и три причины отказа.

**Развилка, и это главная развилка Wave 1:**
- **M ≥ 4** → двигаем продукт: веб, состояния, тестеры.
- **M ≤ 3** → следующие две недели идут в промпты, сценарий и пресеты движения, а **не** в веб.
  Веб поверх плохого ролика не продаётся.

Эта задача стоит один день и стоит дороже всех таймаутов вместе взятых.

### Дни 4–9 — продукт вокруг генерации

Что именно делать — зависит от развилки дня 0. Если база — `ai video`, здесь переносятся
субтитры, Director и умный бюджет визуала. Если база — v3, здесь строится доставка.

Параллельно, независимо от базы:
- **Учёт затрат.** Append-only JSONL по `project_id`: одна строка на каждый платный вызов —
  `{время, project_id, стадия, провайдер, модель, единицы, цена за единицу, стоимость, попытка,
  результат}`. Прайс-лист — один словарь в конфиге с датой обновления. Это ~50 строк кода и один
  декоратор вокруг вызовов провайдеров. Без него ни одну метрику для акселератора посчитать
  физически нельзя, а первый счёт от провайдера придёт агрегатом за месяц.
- **Идемпотентность.** Ключ на создание проекта, дедупликация по хешу промпта и настроек в окне
  10 минут. Блокировка кнопки на фронте — только вторая линия обороны, серверная проверка
  обязательна. Двойной клик — это ровно ×2 к себестоимости ролика.

### Дни 10–12 — проектирование ожидания

При 5–10 минутах генерации ожидание — это половина продукта, а не техническая деталь. Три
решения:

1. **Первое доказательство за ≤ 60 секунд.** Как только готов первый кадр — показать его.
   Человек, увидевший свой кадр, ждёт дальше; человек, смотрящий на полоску, уходит.
2. **Ожидание не блокирующее.** Ссылка живёт, вкладку можно закрыть, при готовности —
   уведомление. Это дешевле, чем ускорять конвейер.
3. **Честный ETA из замеров**, а не фейковая полоска. После 20 прогонов известен p50 по каждой
   стадии — показывать «осталось ~4 мин».

Отдельно для демо-дня: 3–5 роликов сгенерировать заранее. Живая генерация на сцене — это риск
без выигрыша.

### Дни 13–14 — вход тестеров

**Входной критерий, без которого тестеров не зовут:** 20 собственных прогонов подряд, из них
≥ 17 завершились успешно, p50 времени замерен, себестоимость одного успешного ролика известна.

Звать **пять** человек, не десять. Первые пять покажут 80% проблем, и вы сожжёте меньше
контактов на сырой версии — второго первого впечатления не будет.

Каждому — конкретная задача («сделай ролик, который ты реально выложишь»), а не «попробуй».
С каждого собрать три вещи: выложил бы да/нет, сколько попыток сделал, на каком месте
раздражился. И один раз посмотреть запись экрана — это дороже десяти опросов.

### Что вырезано из Wave 1

Вырезано сегодня, без потери ценности:

1. **Весь премиум-путь** — Runway, Kling, PixVerse, Veo, Hailuo, и вместе с ним задачи про их
   таймауты. В Wave 1 безопасный режим — единственный режим, переключателя в интерфейсе нет.
2. **Выбор формата кадра** — один формат. Чинить мультиформат ради Wave 1 дороже, чем
   зафиксировать один.
3. **Выбор языка** — один, тот, на котором говорят ваши первые пять тестеров.
4. **Свободный слайдер длительности** — два пресета, 15 и 30 секунд. 60 секунд — это вдвое
   дольше ждать и вдвое дороже ошибка.
5. **Фоновая музыка** — за флагом, по умолчанию выключена (см. юридический риск в
   [PROVIDERS_LEGAL.md](PROVIDERS_LEGAL.md)).
6. **Отдельный staging-контур** — одно окружение, вы не команда из десяти человек.

### Заморозка движка — по слоям, а не целиком

В версии 1.0 Wave 1 заканчивался пунктом «заморозить движок», но без критерия разморозки. Когда
через две недели тестеры скажут «ролик так себе» — а это самый вероятный исход — такая заморозка
либо нарушается в первый же день, либо блокирует единственный канал улучшения продукта.

| Заморожено (до конца Wave 1) | Меняется свободно |
|---|---|
| архитектура стадий | тексты промптов Director и PromptDirector |
| состав активного пути | пресеты стиля |
| набор провайдеров | параметры движения камеры и переходов |
| сигнатуры между стадиями | длительности сцен, голос и его настройки |

**Правило:** если изменение живёт в конфиге или в строке промпта — можно. Если требует трогать
`.py` на активном пути — нужен git-чекпойнт и повод в виде провалившегося прогона.

## 6. Definition of Done — проверяемая версия

Версия 1.0 описывала счастливый путь одним предложением: «открыл URL → ввёл идею → Generate →
прогресс → видео → скачал». В нём нет ни одного числа и ни одного состояния, в котором
пользователь реально окажется. Это не критерий готовности, а скриншот из презентации.

Готово — когда **каждое** утверждение ниже проверено руками:

1. Незнакомый человек **с телефона** получает MP4 без вашей помощи и без инструкции.
2. p50 времени генерации 30-секундного ролика ≤ **X** минут, p90 ≤ **Y**. X и Y **замерены**, а
   не выдуманы, и показаны пользователю как «осталось ~N мин».
3. На экране ожидания **никогда** нет крутилки без текста дольше 20 секунд — всегда видна
   текущая сцена и уже готовые кадры.
4. Кнопка «Отменить» останавливает задачу между сценами; воркер проверяет флаг перед каждым
   платным вызовом.
5. Повторный клик по «Создать» не создаёт второй платной задачи — проверено серверной
   дедупликацией, а не блокировкой кнопки.
6. Закрытая вкладка не убивает генерацию; по ссылке результат находится позже.
7. При падении на четвёртой сцене пользователь видит внятное состояние ошибки, а не пустой
   экран, и уже готовые сцены не оплачиваются повторно.
8. Ключи провайдеров не уходят в браузер и не появляются в логах.
9. Известно, сколько дней живёт результат, и это написано на странице.

### Почему `ffprobe` — недостаточный критерий

Чёрное видео нужной длительности с тишиной в звуке и без единого субтитра проходит `ffprobe`
идеально: контейнер валиден, длительность верна, кодеки на месте. Вы получите зелёный прогон и
поверите ему.

Минимальные содержательные проверки поверх `ffprobe`:

- в финале **> 0** видеопотоков и **> 0** аудиопотоков, разрешение равно целевому пресету;
- длительность в пределах **±20%** от суммы сцен, причём **источник истины — длительность
  голоса**, а запрошенные секунды считаются целью с допуском: расхождение внутри допуска
  **не является багом**;
- последний кадр не совпадает с кадром за две секунды до конца (ловит «замороженный» хвост);
- средняя яркость выборки кадров выше порога (ловит чёрное видео);
- пиковый уровень звука выше порога (ловит тишину);
- если субтитры включены — файл `.srt` непустой и число строк соответствует числу сцен.

## 7. Позиционирование и рынок

### Что проверено

На сентябрь 2026 заявленное отличие уже поставляется конкурентами: InVideo Agent One делает
разбивку на сцены, референсы персонажей, раскадровку, генерацию шотов, голос, музыку и
автоподбор модели из 200+ движков за $17/мес; HeyGen в сентябре 2026 запустил Video Agent —
«один промпт → сценарий, визуал, озвучка, монтаж, доставка». Мультипровайдерный роутинг —
тоже коммодити: fal.ai (600+ моделей), Krea, Higgsfield за $7–19/мес.

**Проверка формулировки.** Если предложение остаётся истинным после подстановки слова «InVideo»
вместо «Horsteppe» — это не позиционирование, а описание категории, и его надо выбросить.
Текущий one-liner версии 1.0 эту проверку не проходит.

### Beachhead: что не так с «cinematic short-form from one prompt»

Это самый переполненный сегмент рынка, с ценовым полом $7–17/мес, без описанного платящего
клиента и с плохим удержанием. Для трёхмесячной программы акселератора, где нужны интервью,
первые клиенты и метрики, это худший возможный выбор.

**Что защитимо здесь на самом деле — не технология, а дистрибуция:** локальный платящий B2B
(продавцы маркетплейсов, агентства в Казахстане), оплата в тенге со счётом для юрлица, и
накапливаемые данные о том, какие ролики принимаются с первого раза.

**Действие до написания веб-интерфейса:** 20 интервью с одним типом клиента и 3 предоплаты по
concierge-схеме. Если 20 интервью не дают ни одной предоплаты — менять beachhead, а не доделывать
движок.

### Три цифры, которые заменяют слово «moat»

До их появления слово *moat* в питче не произносится:

1. **cost per accepted video** по конкретной вертикали;
2. **first-pass acceptance rate** — доля роликов, принятых без перегенерации;
3. список платящих клиентов и их месячный бюджет.

### Про казахский язык

Соблазн «мы то же самое, но на казахском» надо убить сразу: казахский уже закрыт западными
сервисами на уровне озвучки, дубляжа и субтитров. Языковой аргумент разобьётся первой же
проверкой.

Если язык используется в позиционировании — то только как узкая доказанная поломка конкурентов:
прогнать 5 казахских промптов через Fliki и InVideo, зафиксировать конкретные дефекты
(типографика и переносы в субтитрах, терминология, культурный контекст) и выносить в питч
**только найденное**. Без такого теста язык из питча убрать.

## 8. Деньги

Полностью — в [MONEY.md](MONEY.md). Здесь только то, что меняет решения.

**Юнит-экономика определяется ровно одной строкой — премиум-секундами видео.** Всё остальное
(LLM, озвучка, изображения, рендер) в сумме стоит около **$0.12** на 60-секундный ролик и
экономически не имеет значения.

При цене Runway Gen-4.5 $0.12/сек подписка $19–29 арифметически не сходится: при $29/мес и
марже 70% в бюджет помещается ~2.6 ролика в режиме Smart или **один** в режиме Cinematic.
С провайдерами класса PixVerse / Hailuo / Runway Gen-4 Turbo ($0.027–0.05/сек) те же режимы дают
6–10 роликов.

**Следствие:** умный выбор провайдера — это не «будущий moat», а **условие выживания**, и он
обязан попасть в Wave 2 сразу после безопасного режима, а не в раздел «планы».

**Вторая по силе переменная — не цена провайдера, а брак.** Падение доли принятых с первого раза
роликов с 65% до 40% даёт +59% к себестоимости при неизменном прайсе.

**Ценовая архитектура, которая сходится:** безлимитный безопасный режим в базовой подписке
(себестоимость $0.14, маржа ~99%) + премиум-секунды отдельным метрируемым пакетом + BYOK для
агентств. Продавать надо монтаж и режиссуру, где маржа 95%+, а не секунды генерации, где вы
проиграете гонку «кредитов за доллар» игрокам с венчурными деньгами.

## 9. Провайдеры

Юридика, лицензии и права на результат — в [PROVIDERS_LEGAL.md](PROVIDERS_LEGAL.md).
**Это блокер первого платежа, а не «вопрос масштабирования».**

Кратко о том, что требует действия немедленно:

- **Pollinations** — бесплатный community-сервис без SLA и без гарантий; он проксирует чужие
  модели, и лицензия результата определяется моделью за ним. Строить на этом платный продукт,
  не зная, что именно вам отдают, нельзя.
- **ElevenLabs** — коммерческие права на сгенерированное аудио есть только на платных планах.
  Перевести на платный план **до следующего демо**.
- **Музыка** — самая вероятная причина претензии, и в версии 1.0 её не было вообще. «Royalty-free»
  почти никогда не покрывает право встроить трек в чужое видео и раздать его конечным
  пользователям. До решения этого вопроса музыка выключена по умолчанию.
- **Права клиента на ролик** — фразу «вы получаете полные авторские права» писать нельзя:
  чисто AI-сгенерированный контент без существенного человеческого вклада не охраняется
  авторским правом в ряде юрисдикций. Это свойство технологии, а не дефект сервиса, и говорить
  об этом надо честно.

Отдельное противоречие, которое надо снять: версия 1.0 запрещала пополнять fal.ai, а вторая
кодовая база целиком на нём стоит. Одно из двух должно быть отменено явно.
