# АУДИТ: что из github.com/higgsfield-ai применимо к Horsteppe

**Дата:** 2026-09-19 · **Среда:** mac
**Исследовано:** 9 репозиториев организации, два склонированы и прочитаны построчно

> Документ отвечает на один вопрос: **что из этого мы ещё НЕ используем, но можем
> использовать, чтобы Horsteppe стал заметно сильнее.**

|---|---|---|---|
| `higgsfield` | 4 600 | Jupyter | **Нет.** Это фреймворк обучения моделей на кластерах GPU, к генерации видео отношения не имеет |

видео из кадра**. Это ровно та возможность, ради которой всё затевалось, и до
сегодняшнего дня мы о ней не знали.

## 2. Контракт API — разобран до поля

Источник: `docs.higgsfield.ai/docs/openapi.json`, версия 2.0.0, плюс чтение
исходников SDK.

**Авторизация:** заголовок `Authorization: Key {api_key_id}:{api_key_secret}`.
SDK читает их из `HF_KEY` либо из пары `HF_API_KEY` + `HF_API_SECRET`.

**Запрос:** `POST https://api.higgsfield.ai/{модель}` → `{request_id, status_url,
cancel_url}`. Ответ асинхронный.

**Опрос:** `GET {status_url}` → `{status, video: {url}, images: [...], error}`.

**Отмена:** `POST {cancel_url}`. Начатую генерацию отменить нельзя, стоящую в
очереди — можно.

**Модели «кадр → видео»** и их поля (обязательные помечены звёздочкой):

| Модель | Поля |
|---|---|
| `kling-video/v2.5-turbo/pro/image-to-video` | `prompt`*, `image_url`*, `duration` (5 или 10), `cfg_scale` (0…1, по умолчанию 0.5), `negative_prompt` |
| `kling-video/v2.5-turbo/standard/image-to-video` | то же |
| `minimax/hailuo-2.3/standard/image-to-video` | `prompt`*, `image_url`*, `duration` (6 или 10), `prompt_optimizer` |

Есть и текстовые варианты тех же моделей.

**Статусы:** `queued`, `in_progress`, `completed`, `failed`, `canceled` и
отдельно **`nsfw`**.

## 3. Чего мы не используем, хотя можем

Найдено семь пробелов. Первые четыре — прямые дефекты нашего кода, которые
объясняют уже наблюдавшиеся провалы.

### 3.1. Отдельный исход NSFW

У Higgsfield это **терминальный статус**, а не ошибка сети. У нас любой отказ
провайдера выглядит одинаково, и цепочка честно идёт к следующему провайдеру —
платит второй раз за тот же отклонённый кадр. Повтор здесь бессмыслен: кадр,
отклонённый по содержанию, отклонит и сосед.

### 3.2. Промпт для видео должен описывать только движение

Из `skills/higgsfield-generate/references/prompt-engineering.md`:

> `--start-image` anchors the first frame. Prompt describes motion.
> **Don't redescribe the static frame — model already has it.**

Мы передаём в `video_prompt` действие сцены и закадровый текст. Модель получает
картинку и её же описание словами — и тратит внимание на пересказ вместо
движения.

### 3.3. Длина промпта

> Keep it under ~200 tokens. **Models distort with very long prompts.**

Наш промпт кадра — это описание мира плюс сцена плюс крупность. На замерах он
выходит в 400–600 знаков только заголовком. Это прямо объясняет, почему кадры
получались пустыми и «никакими»: модель искажает длинные задания.

### 3.4. Отрицания в промпте не работают

> Most models don't expose a `negative_prompt`. Phrase positively:
> instead of "no people" → "uninhabited landscape".

У нас в промпте: `no text, no captions, no logos`, и я добавил туда же запрет на
лица. Это ровно тот приём, который документация называет неработающим — и это
совпадает с наблюдением: модель продолжала рисовать женщину, пока запрет не
переехал в описание поля схемы.

**Важная оговорка:** у моделей Kling на этом API `negative_prompt` **есть**.
Значит, правило «формулируй положительно» относится к промпту картинки, а
запреты нужно переносить в отдельное поле там, где оно поддерживается.

### 3.5. Отмена по таймауту

SDK умеет `cancel`. Мы при истечении времени просто бросаем запрос — а он
продолжает считаться и тратить деньги. Отмена ставит точку.

### 3.6. Повторы с растущей паузой

`skills`-SDK повторяет на кодах 408, 429, 500, 502, 503, 504 с экспоненциальной
паузой. В нашем шаге видео повторов нет вовсе: единственный 429 роняет кадр.

### 3.7. Словарь режимов съёмки товара

`higgsfield-product-photoshoot` описывает десять режимов, из которых нам прямо
подходят четыре: `product_shot` (студия), `lifestyle_scene` (товар в среде),
`closeup_product_with_person` (руки, крупно), `conceptual_product` (левитация,
всплеск). Это готовая замена нашим самодельным формулировкам.

## 4. Что берём и почему

| Возможность | Берём | Обоснование |
|---|---|---|
| Higgsfield как провайдер видео | **Да** | Это Kling 2.5 Turbo Pro напрямую у источника; схема полей известна точно, гадать не нужно |
| Статус NSFW как отдельный исход | **Да** | Экономит деньги и не врёт пользователю про «провайдер недоступен» |
| Промпт движения для видео | **Да** | Прямая причина слабого результата |
| Ограничение длины промпта | **Да** | То же |
| Отмена по таймауту | **Да** | Деньги |
| Повторы с паузой | **Да** | Один 429 не должен ронять кадр |
| Режимы съёмки товара | **Да, частично** | Берём словарь, а не их backend-обогатитель: он за их API |
| Marketing Studio, Virality Predictor | **Нет** | Доступны через консоль и CLI, в публичном REST их нет |
| Agent API | **Нет** | Многошаговые творческие сессии — не наш сценарий |
| Фреймворк `higgsfield` | **Нет** | Обучение моделей, не генерация |

## 5. Порядок внедрения

1. **Провайдер Higgsfield** — `config.py`, `steps/video_step.py`, тесты.
   Цепочка становится `higgsfield → fal → replicate`.
2. **Дисциплина промптов** — `steps/shot_plan.py` (движение отдельно от
   картинки, ограничение длины), `product_brief.py` (положительные
   формулировки), тесты.

Каждый шаг — отдельный коммит с прогоном всего набора тестов.

## 6. Второй проход: что нашлось после интеграции

Повторный аудит потребовал техзадание, и он оправдался — нашлись три вещи.

### 6.1. Страница анти-бота вместо JSON — **исправлено**

Их разбор сбоев описывает случай: вместо ответа API приходит HTML с проверкой
CloudFlare/DataDome. Наш код звал `.json()` напрямую, и разбор падал бы
исключением **мимо цепочки провайдеров** — кадр терялся бы там, где сосед мог
справиться. Теперь это обычный отказ, и очередь идёт дальше.

### 6.2. `ip_detected` — **исправлено**

В `openapi.json` этого статуса нет, но в их руководстве он стоит рядом с
`nsfw` как ещё один отказ по содержанию. Принимаем оба: новый повод для
отказа не должен притворяться сбоем сети и уводить цепочку к платному соседу.

### 6.3. Кадр конца — **доступно, но не через наш интерфейс**

`kling3_0` принимает `start_image` **и** `end_image`: камера интерполируется
между двумя кадрами. У нас в таблице кадров колонка `last_frame_reference`
заведена и пустует.

Взять нельзя: в публичном REST у `kling-video/v2.5-turbo` такого поля нет,
возможность живёт только в их CLI и консоли. Записано как известный резерв —
если появится REST-модель с `end_image`, колонка уже ждёт.

### 6.4. Оценка стоимости до запуска — **недоступно**

`higgsfield generate cost` возвращает оценку в кредитах, ничего не запуская.
В REST такого пути нет (в `openapi.json` всего восемь адресов). Наш
собственный предварительный расчёт остаётся единственным источником цены.

## 7. Чего это не решает

Higgsfield — платный сервис. Аудит снимает технические препятствия и делает
интеграцию точной, но кредиты на счёте всё равно нужны. Бесплатного тарифа в
документации не заявлено; SDK упоминает `InsufficientCreditsError` как штатную
ситуацию.

Зато выбор у основателя теперь из трёх касс, а не из одной: Higgsfield, fal
(минимум $10) и Replicate (счёт по факту).
