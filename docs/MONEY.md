## 1. Главный факт

**Себестоимость ролика — это премиум-секунды видео. Всё остальное шум.**

| Статья | Стоимость на 60-секундный ролик | Доля |
|---|---:|---|
| LLM (сценарий, сцены, промпты) | ~$0.02 | шум |
| Изображения | ~$0.06 | шум |
| Озвучка (ElevenLabs Flash, ~700 символов) | ~$0.04 | шум |
| Локальный рендер FFmpeg | ~$0.00 | шум |
| **Итого без премиум-видео** | **~$0.12** | — |
| Премиум AI-видео | **$0.6 – $8.6** | **99%** |

Отсюда весь дизайн продукта: безопасный режим стоит копейки и его можно раздавать почти
безлимитно; премиум-секунды — это метрируемый ресурс, который надо считать поштучно.

Расчёт включает брак: доля принятых с первого раза 65% (коэффициент ×1.54 на клип) и 15% полных

| Режим | 30 секунд | 60 секунд |
|---|---:|---:|

| Режим | 60 секунд |

### Что это значит для подписки

При цене **$29/мес** и целевой марже 70% бюджет себестоимости — **$8.70 на пользователя**.

| Провайдер | Сколько Smart-роликов помещается в месяц |
|---|---:|
| Runway Gen-4.5 | **2.6** |
| PixVerse / Hailuo / Turbo | **6–10** |

> **Вывод.** Умный выбор провайдера — не будущая фича, а условие существования продукта.
> Он обязан появиться сразу после безопасного режима.
> Целевой потолок зафиксировать константой в коде: `cost_per_accepted_video ≤ $1.00` для 60 с Smart.

## 3. Что ломает экономику первым

Не цена провайдера, а **премиум-секунды на принятый ролик**:

```
premium_seconds_per_accepted_video =
    (число премиум-сцен) × (длина клипа) × (попыток на принятый клип) × (полных перезапусков)
```

Чувствительность для Smart 60 с на Runway Gen-4.5:

| Доля принятых с первого раза | Себестоимость |
|---:|---:|
| 90% | $1.67 |
| 80% | $1.86 |
| **65%** | **$2.26** |
| 50% | $2.90 |
| 40% | $3.59 |
| 30% | $4.74 |

Падение с 65% до 40% — совершенно реалистичное для генерации видео без человека в цикле — это
**+59% к себестоимости** при неизменном прайсе.

### Четыре числа, которые надо инструментировать с первого же прогона

1. `premium_seconds_per_accepted_video`
2. `attempts_per_accepted_clip`
3. `full_rerun_rate`
4. `cost_per_accepted_video`

Это же — первый слайд в акселераторе.

### Жёсткие ограничители в коде

```
premium_seconds ≤ 10  на ролик в режиме Smart
premium_seconds ≤ 25  на ролик в режиме Cinematic
```

Независимо от того, что решил планировщик визуального бюджета.

## 4. Налог на отсутствие resume и идемпотентности

Это не техдолг, это прямая строка себестоимости:

- **Падение на монтаже** заставляет заново платить за LLM + изображения + видео + озвучку, хотя
  сгенерированные клипы уже лежат на диске.
- **Двойной клик** = две платные задачи = ровно ×2 к себестоимости ролика.

В модели заложено 15% полных перезапусков — это +$1.12 к Cinematic-ролику. При реальных 30% на
неотлаженном конвейере — уже +$2.2.

Два дешёвых фикса:

1. **Идемпотентность** — ключ запроса на создание проекта, дедупликация по
   `(user_id, prompt_hash, settings_hash)` в окне 10 минут. Блокировка кнопки на фронте — вторая
   линия обороны, не первая.
2. **Кэш артефактов по `project_id`** — после стадии видео сохранять манифест
   `{scene_id → путь, провайдер, стоимость, prompt_hash}`; при повторном запуске переиспользовать
   клип, если хеш промпта совпал. Это автоматически даёт и resume.

## 5. Учёт затрат (cost ledger)

**Учёт затрат — это не биллинг.** Запрет «не строить биллинг до надёжного завершения задачи» на
него не распространяется. Без него нельзя выбрать ни цену, ни лимиты, а первый счёт от провайдера
придёт агрегатом за месяц, из которого невозможно вытащить стоимость одного ролика.

Формат — append-only JSONL, одна строка на каждый платный вызов:

```json
{"ts":"2026-09-06T12:00:00Z","project_id":"...","job_id":"...","stage":"video",
 "provider":"runway","model":"gen-4.5","units":5,"unit":"sec","unit_price":0.12,
 "cost_usd":0.60,"attempt_no":1,"outcome":"ok"}
```

Прайс-лист — один словарь в конфиге с датой обновления, чтобы пересчитать историю при смене
тарифов. Объём работы — около 50 строк и один декоратор вокруг вызовов провайдеров.

Дополнительно: показывать внутренний счётчик «этот ролик стоил $X» прямо в интерфейсе.

## 6. Бесплатный триал

Расчёт на 1000 регистраций, активация 60% (600 человек реально запускают генерацию):

| Схема триала | Прямые расходы | С учётом абьюза (×2.5) |
|---|---:|---:|
| Только Safe, 3 генерации | $249 | $622 |
| 1 Smart на Runway 4.5 + 2 Safe | $1 523 | $3 806 |
| 3 Smart на Runway 4.5 | $4 070 | $10 176 |

Против этого: 1000 регистраций при конверсии 2.5% дают 25 платящих по $29 = **$725 MRR**.

> Премиум-триал сжигает от 2 до 14 месяцев выручки когорты — ещё до себестоимости платящих
> и до стоимости привлечения.

**Правило:** премиум-провайдер недоступен без привязанной карты или явной ручной выдачи.
Триал = безопасный режим, с водяным знаком и явной кнопкой «сделать кинематографично → нужен план».

Плюс до публичного запуска:
- бюджет на аккаунт **в долларах**, а не в сценах, проверяемый **перед** платным вызовом;
- общий дневной лимит расходов по проекту с аварийным выключателем;
- ограничение частоты: одна генерация в N минут на аккаунт.

Текущая защита — глобальная константа `MAX_AI_VIDEO_SCENES = 1` — это не квота на аккаунт.
При нескольких пользователях она не защищает ни от чего. Заменить на функцию
`allowed_premium_seconds(user, project)`.

## 7. Инфраструктура

При малом объёме опасна не цена API, а простаивающий сервер:

| Объём | Стоимость рендера на ролик (один сервер ~$185/мес) |
|---:|---:|
| 100 роликов/мес | $1.85 |
| 500 роликов/мес | $0.37 |

**Правило:** не поднимать второй воркер до 300+ роликов в месяц. При меньшем объёме брать самую
маленькую машину с выделенными ядрами и мириться с очередью — простой дороже задержки.

## 8. Ценовая архитектура, которая сходится

Конкуренты продают секунды с венчурной субсидией: Higgsfield $19/мес, InVideo Plus $20/мес за
50 минут генерации, Pika от $8/мес. Соло-основатель без внешних денег не выигрывает гонку
«кредитов за доллар».

Зато у вас есть то, чего в их цене нет: **голос + субтитры + таймлайн + переходы + аудиомикс +
экспорт**. Себестоимость этого — те самые $0.12 за 60 секунд, и она не растёт с качеством.
Это и есть часть с маржой 95%+.

| Уровень | Что продаём | Себестоимость | Маржа |
|---|---|---:|---:|
| Базовая подписка $19–29 | **безлимитные** ролики в безопасном режиме | $0.14/ролик | ~99% |
| Премиум-секунды | пакет (60 сек/мес в Creator, 300 в Pro $79) + докупка по $0.25–0.35/сек | $0.027–0.12/сек | 2.5–6× |
| Агентства | BYOK — свой ключ провайдера | $0 | премиум уходит из P&L |

Продавать надо монтаж и режиссуру, а не генерацию.

**Отдельный риск, который надо снять:** весь маржинальный безопасный режим стоит на Pollinations —
бесплатном сервисе без гарантий. Если он исчезнет или закроется, исчезнет и режим с маржой 99%.
Нужен запасной провайдер изображений с известной ценой.

## 9. Платежи: вход и выход

| OpenRouter / Anthropic | | | | |

| Supabase / Vercel | | | | |

Отдельные карты с жёсткими лимитами на каждого провайдера. Отдельные ключи для разработки и
для продакшна — тогда компрометация ключа разработчика не останавливает продукт.

### Входящие — как принимать деньги

**Stripe не поддерживает создание аккаунтов для Казахстана.** Стандартный SaaS-путь закрыт по
умолчанию. «Ручная оплата» на практике означает перевод на карту физлица — это нельзя ни
показать в акселераторе, ни масштабировать.

Три пути, надо выбрать один и записать выбор:

| Путь | Плюсы | Минусы |
|---|---|---|
| **(а) Merchant of record** — Paddle, Lemon Squeezy, FastSpring | сами решают налоги, инвойсы и мировые платежи; Stripe не нужен | комиссия выше; проверить актуальный список стран для продавца из РК |
| **(б) Локальный эквайринг** под ИП/ТОО — Kaspi Pay, Freedom Pay, ePay | работает для клиентов из РК, подходит для первых concierge-продаж | не подходит для международных клиентов |
| **(в) Иностранное юрлицо** ради Stripe | полный доступ к мировому рынку | дорого и долго; преждевременно |
